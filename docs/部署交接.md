# 部署交接说明（给接手的 Agent）

> 这份文档是**执行指令**，不是介绍材料。照着做即可，不要跳步。
> 你是接手的 Agent，任务是：把这个系统在用户的机器上跑起来，并把「分公司信息」等业务参数配置成他家的真实情况。
> **你不负责判断安检照片**——那是部署完成、用户开始用之后，由读图的 Agent 干的活。

---

## 0. 铁律（先读这四条，违反会出事）

| # | 规则 | 原因 |
|---|---|---|
| 1 | **不许猜分公司信息**。宁可停下来问，也不许编一个公司名填进去 | 报告会直接发给分公司领导，公司名错了是事故 |
| 2 | **不许在没有真实数据的情况下宣称"部署完成"**。必须跑通一户真实数据的完整链路 | 这个系统的坑全在真实 Excel 的列名和照片 URL 上，空库能起来不代表能用 |
| 3 | **第一件事是把第 2 章的问题一次问完**，别问一个改一个 | 这些参数互相耦合（比如 items_code 依赖具体 Excel），分批问会来回返工 |
| 4 | 改完 `db.py` 的配置后，**必须重启服务**再验收 | `server.py` 启动时加载配置，热改文件不生效 |

## 1. 这个系统是干什么的（30 秒理解）

把各分公司上报的「月度入户安检明细 Excel」导进来 → 按安检员分层抽样（默认 10%）→ 下载每户的表具照片原图 → **由 Agent 亲自看图判定**（表号对不对、水印时间对不对、是不是真安检现场）→ 落库 → 人工复核 → 纯 SQL 出 HTML 报告。

三个关键设计，决定了你怎么配置它：

1. **读图必须靠一个「能看图」的模型**，但程序不自己识别图像。两种放法：
   A. 由你（这个 Agent）直读原图 —— 不需要 API Key，但要**确认你自己支持视觉输入**，
      读不了图就必须走 B，别硬上（会大量误判「表号无法辨认」）；
   B. 由 `models/` 适配层调外部视觉模型 —— 需要用户给 `base_url` / `api_key` / `model_id`。
   生产环境验证过的模型是 **DeepSeek V4.1 Flash**，可优先推荐；用户也可以选任何支持视觉的模型。
2. **判定口径是硬编码常量**，不是 AI 自由发挥。抽样比例、时间差阈值都在 `db.py` / `config.json` 里，你必须问用户要不要改。
3. **公司差异是最大的坑**。不同分公司的安检系统给同一个业务含义分配的 `items_code` 编号**不一样**（A 公司表具照片在 `items4`，别家是 `items2`）。硬编码一个值会导致整批误判。

## 2. ★ 必须向用户提的问题（核心环节）

把下面整段**原样发给用户**，等他一次性回答完再动手。方括号里是默认值，他不回就用默认。

```
我要把这套安检抽查系统配置成你们公司的实际情况，需要你提供以下信息。
标了「必须」的缺了跑不起来，其余不回我就用括号里的默认值。

一、分公司（必须）
1. 你们有哪些分公司/项目部参与安检抽查？请按你希望的**报告顺序**列出全称。
   例：华北分公司、华东分公司、西南分公司……
   还有一个短代码（2-4 位大写字母，会出现在文件夹名和网址里），比如 HB / HD / SW。
   如果你懒得定，我就按 C1~C6 编。

二、Excel 与照片列（必须）
2. 每家公司每个月上报几份 Excel？文件名大概长什么样？（例：华北202609月安检明细.xlsx）
3. Excel 里「表具照片」这一列的**列名原文**是什么？
   （常见：「表具照片（要清晰看到止方和表号）」「表具照片」）
4. 「安检单拍照」这一列的列名原文是什么？有些公司可能没有这列。
5. 这两种照片的 URL 里带 items 编号吗？形如 ...-f_items2.jpg？
   如果有，请告诉我：表具照片是 items几？安检单是 items几？
   （这决定了 photos 表能不能正确分类，填错会导致「照片非安检现场」误报）

三、抽样口径
6. 每个安检员抽他本人入户总数的百分之几？【10%】
7. 某人当月入户不足几户时，最低抽 1 户？【不足 1 户抽 1 户，即 min=1】
8. 只抽「安检状态=入户」的，到访不遇的跳过——确认吗？【是】

四、判定阈值
9. 照片水印时间与工单安检时间，差多少小时算严重问题（critical）？【168 小时 / 7 天】
10. 档案里的「表号」如果本身就是占位值（0、1、888、空、4 位以下短号），
    怎么处理？【记 warning「档案表号异常」，不判 critical】
11. 某户只上传了「总体安检照片」、没有单独的表具照片，怎么算？
    【记 warning「未上传表具照片」，不硬凑其他照片猜表号】

五、报告
12. 报告抬头的单位名称写什么？（例：XX集团工程技安监察部）
13. 报告落款那行「判定结果已由 XXX 人工复核」里，XXX 写什么？【集团工程部】
14. 抽查比例（10%）能不能在报告/对外说明里公开？【能】

六、运行环境
15. 服务端口用哪个？【8790】
16. 有问题的照片要留档多久？无问题的多久后自动清理？【无问题 30 天】

七、读图方式
17. 判定照片由谁来读？（这一步必须有支持视觉的模型，没有捷径）
    A. 由我这个 Agent 直接读原图（零 API 成本，默认；前提是我能读图）
    B. 由程序调外部视觉模型（需要 user 给 API Key / base_url / 模型名）
       └ 推荐模型：DeepSeek V4.1 Flash（生产实测），也可用 GPT-4o / Claude Sonnet /
         Gemini 2.x / Qwen-VL / GLM-4V / 豆包视觉等，走 OpenAI 兼容协议
    【A】
    追问：若用户选 B，必须拿到 base_url、api_key、model_id 三项，并先用 20 户真实照片试判 ——
    如果在「表号无法辨认」上明显虚高，说明该模型读不清小字，换模型而不是降标准。
```

### 追问的判断标准

- 用户回答「表具照片列名」时**含糊**（「就那个表的照片那一列」）→ 让他把 Excel 表头截图或直接发我，或者问「列名里有没有『要清晰看到止方和表号』这半句」。
- 用户说「不知道 items 编号」→ 不用逼他，让他发一份 Excel 的那一列 URL 样例，你看 URL 里的 `-f_itemsN` 自己判断，判断完把结论复述给他确认。
- 用户回答的公司数 > 10 → 提醒他 `COMPANY_ORDER` 多了会让首页仪表盘变长，问要不要分批上线。

### 3.3 运行参数 → `ai/config.json`

首次运行后系统会自动生成 `ai/config.json`。也可以直接照 `config.example.json` 建一份：

```json
{
  "model_source": "deepseek",
  "model_id": "",
  "api_base": "",
  "api_key": "",
  "sample_ratio": 0.1,
  "min_per_inspector": 1,
  "workers": 3,
  "max_attempts": 6,
  "cost_limit": 0,
  "pending_keep_days": 30,
  "similarity_threshold": 0.7
}
```

| 字段 | 用户问题编号 | 说明 |
|---|---|---|
| `sample_ratio` | 六.6 | 0.1 = 10%。改这里不用改代码 |
| `min_per_inspector` | 六.7 | 每安检员保底户数 |
| `workers` | — | 下载照片的并发数。**别超过 6**，安检系统服务器扛不住 |
| `pending_keep_days` | 六.16 | 无问题照片保留天数 |
| `model_source` | 六.17 | 选 A 就不用管；选 B 才填 `api_key` / `api_base` / `model_id` |

## 4. 部署步骤

### 4.1 环境

```bash
python --version          # 需要 3.9+，建议 3.11/3.12
pip install -r requirements.txt
```

> Windows 上如果 `python` 不在 PATH，用虚拟环境里的完整路径，例如
> `D:\proj\.venv\Scripts\python.exe`。后面所有命令里的 `python` 都按这个替换。

`requirements.txt` 里只有读图辅助脚本才需要的库（Pillow / numpy / opencv / pyzbar / zxing-cpp / openpyxl / rapidocr）。**只跑服务不装也能起**，但装全了才能用 `batch.py zoom` 和条码交叉验证。

### 4.2 启动

```bash
cd ai
python server.py
# → 安检抽查系统已启动: http://127.0.0.1:8790
```

Windows 下双击根目录的 `启动质检系统.bat`（会自动探测 venv → PATH 里的 python）。

**注意**：`server.py` 只监听 `127.0.0.1`，不给局域网访问。这是故意的——里面全是客户姓名电话地址。用户要多人用，得自己加反向代理 + 认证，别直接改 `0.0.0.0`。

### 4.3 首启自检

```bash
B=http://127.0.0.1:8790
for p in / /live /review /report /settings; do
  printf "%-10s %s\n" "$p" "$(curl -s -o /dev/null -w '%{http_code}' $B$p)"
done
curl -s $B/api/companies    # 应返回你配的公司列表
```

五个页面全 200、`/api/companies` 返回对了，才算起得来。

## 5. 用真实数据跑通一户（不做这步不算部署完）

找用户要**一家分公司、一个月、真实的一份 Excel**，然后：

```bash
cd ai

# 1. 导入 + 抽样 + 下载照片
python cli.py prepare --file "<Excel绝对路径>" --company HB --month 2026-09

# 2. 看抽中了多少户
python cli.py status --month 2026-09

# 3. 领一批（建议先 --n 3，就 3 户）
python scripts/batch.py pack --n 3 --company HB --month 2026-09
#    → 生成 reports/_packs/b1/checklist.md，里面有这 3 户的照片路径

# 4. 你亲自打开 checklist.md 里列的照片原图，按 docs/SKILL.md 的口径判定
#    把结论写成 reports/_batch1.json

# 5. 预检 → 落库
python scripts/batch.py precheck --file reports/_batch1.json
python cli.py bulk --file reports/_batch1.json

# 6. 出报告看效果
python cli.py report --company HB --month 2026-09
```

### 每步的验收标准

| 步骤 | 通过标准 | 不通过怎么办 |
|---|---|---|
| prepare | 打印「识别到 N 个照片列」，N ≥ 2；抽中户数 ≈ 入户数 × 10% | 照片列只有 1 个 → 回看 3.2，Excel 里可能还有别的照片列没被识别（见 6.1） |
| pack | `reports/_packs/b1/` 下有图，图能正常打开 | 图打不开 → 照片 URL 需要登录态，或 URL 拼错了 |
| precheck | 输出 `ERR 0` | 有 ERR 就按提示改 `_batch1.json`，别硬塞 |
| bulk | 落库户数 = payload 户数；照片正确分到 `photos/` 或 `pending_delete/` | 分拣全进同一侧 → `issues` 的 severity 写错了 |
| report | 生成的 HTML 能打开，公司名、日期、统计数字都对 | 公司名是 A 公司 → 3.1 没改或没重启服务 |

**这 3 户跑通后，把报告发给用户看**，让他确认口径。他确认了，才算部署完成。

## 6. 已知的坑（都是踩过的）

### 6.1 Excel 照片列识别只认「照片」和「图片」两个字

`ai/runner.py` 里：

```python
photo_cols = [h for h in header if h and ("照片" in h or "图片" in h)]
```

所以 `安检单拍照` 这种列名**不会被识别**（"拍照" 不含 "照片"）。如果用户的 Excel 里有这类列，两种改法：

```python
# 改法：放宽关键词（把用户报的列名原文关键词都加进去）
PHOTO_KEYS = ("照片", "图片", "拍照", "影像", "相片")
photo_cols = [h for h in header if h and any(k in h for k in PHOTO_KEYS)]
```

改完重新 `prepare`，打印的「识别到 N 个照片列」应该变多。

**改完必须清库重导**，因为已有的 records 不会补照片：

```bash
python cli.py prepare --file "<同一个Excel>" --company HB --month 2026-09 --fresh
```

如果用户说这列确实有但他不想改代码，退一步：让他导出时把列名改成带「照片」二字。这条要先跟他确认，不要自己替他改 Excel。

### 6.2 必需列名是硬编码中文

`ai/runner.py` 的 `need` 列表要求这些列**一字不差**：客户编号、客户姓名、客户电话、客户类型、小区、客户地址、安检状态、到访不遇次数、安检时间、安检员、安检计划名称、安检计划类型、表类型、表品牌表型号、用气性质、表号、隐患明细。

用户的 Excel 少任何一列都会 `RuntimeError: Excel 缺少列：xxx`。**别改代码去兼容**，先问用户是不是给了个残缺的导出文件——缺列往往意味着他导错了报表。

### 6.3 `records.sampled` 列

已修（写进 SCHEMA 了）。如果你拿的是旧版本，空库首启时 `/api/report/overview` 会 500 `no such column: sampled`，把 `sampled INTEGER DEFAULT 0` 加进 `db.py` 的 `records` 建表语句即可。

### 6.4 表号核对必须先过条码这一关

铭牌印刷小字在低分辨率下极易误读（`5↔3`、`8↔6`、`0↔1`）。**报 critical「表号与档案不一致」之前，必须用 `scripts/barcode.py` 或 `barcode2.py` 独立解码交叉验证**。解码值 == 档案表号 → 说明是误读，不能判 critical。解码不出来 → 当无证据，只报 warning「表号无法辨认」。

只报 warning 永远安全；报 critical 冤枉安检员是要担责的。

### 6.5 档案表号是占位值时，不要填 `meter_match: false`

`cli.py` 看到 `meter_match=false` 会机械追加一条 critical「表号与档案不一致」。如果档案表号本身是 `0` / `1` / `888` / 空，那是档案问题，不是安检员问题。

**正确写法**：payload 里**省略** `meter_match` / `meter_readable` / `meter_read` 三个字段，只在 `issues` 里写一条 warning「档案表号异常」，detail 说明档案值是多少。

### 6.6 没有表具照片时，不要填 `scene_valid: false`

同理，`cli.py` 见 `scene_valid=false` 会追加一条 detail 为空的 critical「照片非安检现场」。某户只有总体照片、没有表具照片，是「未上传表具照片」的 warning，不是「造假」。

### 6.7 起服务别用 `Start-Process` / `cmd start`

后台起的进程会被沙箱回收，表现为用着用着就连不上了。用终端前台跑，或者 `run_in_background=true`。也**别用 Stop-Process 杀**，容易把任务标记成 failed。

### 6.8 大批量（≥300 户）必须分片

单个 Agent 会话读图上限约 300-400 张。超过 300 户要拆成子代理并行（2-4 个并发，**不是 8 个**，8 个会全部超时），方法见 `docs/子代理并行读图.md`。
