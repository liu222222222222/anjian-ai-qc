# 使用说明（操作手册）

面向日常使用者：怎么开、点哪里、每个页面的按钮是干什么的、每月固定动作有哪些。
部署与参数配置看 [`部署交接.md`](部署交接.md)，判定口径与读图规范看 [`SKILL.md`](SKILL.md)。

---

## 一、最快的方式：跟 Agent 说一句话

在支持读图的对话框里说：

```
启动安检抽查 D:/anjian-qc/安检表格/2026-09/<分公司>202609月安检明细.xlsx
```

Agent 会自动完成：导入 → 抽样 → 下载 → **亲自读图逐户判定** → 写库 → 出报告 → 告诉你问题在哪。

不需要配 API Key、不产生额外模型费用（识别用的就是对话框里的那个模型，只要能读图）。
也可以让程序自己调外部视觉模型，见文末「模型来源」。

## 二、自己开网页看

双击根目录 **`启动质检系统.bat`** → 浏览器打开 `http://127.0.0.1:8790/`

首次使用：设置页 → 填模型 API Key → 点「测试模型视觉能力」→ 通过后再运行。
（只有「程序自己调外部 API」才需要填；走 Agent 对话流程不需要。）

## 三、页面清单

| 页面 | 地址 | 用途 |
|---|---|---|
| 总览 | `/` | 选时间范围（单月 / 上月 / 全年 / 上年 / 自定义区间 / 全部）、看六家进度卡片、断点续查状态。**右上角有本地照片清理提醒** |
| 实时看板 | `/live` | **给领导看**：当前户大字展示、通过/提示/问题三色判定、右侧实时流 |
| 人工复核 | `/review` | **逐户过有问题的人**：误判 / 一般提示 / 严重提示 三个按钮<br>键盘：`↑` 一般提示　`↓` 严重提示　`←` 上一户　`→` 下一户　`1` 误判<br>顶栏可切月份，也可切到「专项任务」队列 |
| 月度报告 | `/report` | **两级结构**：顶部「情况说明」（抽查范围 / 人工审核 / 问题发现 / 符合率 四块）+ 各分公司卡片，点进去看该公司报告 |
| 分公司详情 | `/report/detail?company=<代码>` | 单家的问题类型分布、安检员质量、问题明细。**每户一张缩略图，点开浮窗看全部照片**，可按档位 + 安检员筛选 |
| 专项任务 | `/special` | **全量定向复检**：给「分公司 + 月份 + 人员名单」时用，独立库，不动月度数据 |
| 设置 | `/settings` | 切换模型、抽样比例、并发、费用上限、待删保留天数 |

## 四、报告怎么看（改版后三个姿势）

**① 每户只放一张图，点开看全部**
卡片/表格里只有一个缩略图，右下角标「共 N 张」。点一下弹浮窗：

- 大图居中，`‹` `›` 或键盘 ←→ 翻页
- 底部一排小缩略图，点哪张跳哪张
- `Esc` 关闭

**② 按人和档位筛**
报告顶部：安检员下拉 + 四个多选按钮（严重提示 / 一般提示 / 正常 / 剔除）。
默认只勾严重和一般，正常和剔除收在折叠区里。

**③ 「情况说明」四块**
抽查范围（全量 → 可查 → 实抽）→ 人工审核（已审 / 比例 / 待审）→ 问题发现（严重户 / 一般户 / 处理口径）→ 符合率。
覆盖率与符合率的分母都是「**可查户**」（入户 + 民用 + 有表具照片），不是全量入户数。

## 五、本地照片与清理（重要）

**报告与页面里的图片一律走公司服务器外链**，本地下载的照片**只为模型读图服务**，判完就该删。

| 目录 | 存什么 | 什么时候清 |
|---|---|---|
| `ai/photos/` | 有问题户的照片 | 内容月份 + 2 个月的 15 号前 |
| `ai/pending_delete/` | 正常户的照片 | 同上（另有 30 天自动过期） |
| `ai/false_positive/` | 判「误判」的照片 | **永不清理**，留档 |
| `ai/special/<任务码>/photos/` | 专项任务照片 | 任务归档后按同一规则清 |

**期限怎么算**

```
9 月安检的内容 → 11 月 15 号前清掉
10 月安检的内容 → 12 月 15 号前清掉
```

**怎么看还剩多少**：总览页右上角垃圾桶按钮

- 灰色 = 没到期，显示 `🗑 本地图片 N 张`
- 黄色 = 7 天内到期
- 红色 = 已逾期

点开能看到每月张数、占用多少 MB、清理期限、还剩几天，还有**文件夹位置**（点一下直接在资源管理器打开）。
点「清理」要**连点两次确认**，删完自动刷新。

> 报告和 Excel 全走外链，删本地照片**不影响任何报告、页面看图和 Excel**。

## 六、每月固定动作

**方式一（推荐）**：跟 Agent 说「启动安检抽查 + 表格路径」，全包。

**方式二（自己点）**：

1. 各分公司 Excel 放进 `安检表格/<月份>/`
2. 总览页 → 选分公司 → 填月份（如 `2026-09`）→ 选源文件 → 开始
3. 跑完去复核页逐户过一遍（三个按钮 / 上下左右键）
4. 复核完去报告页 → 下载各分公司报告发安检领导
5. 要公司回填整改情况：卡片点「导出Excel」→ 发给公司 → 公司只填最后一列「公司反馈」→
   回传后在报告页点「导入公司反馈」写回审核意见
6. 到「内容月份 + 2 个月」的 15 号前，点右上角垃圾桶把本地照片清掉

## 七、Excel 明细表 / 公司反馈回填

- **导出**：报告页每家卡片「导出Excel」，文件名 `安检抽查明细_<公司>_<年月>_<导出日期>.xlsx`
- **两个 sheet**：① 问题户（一户一行：判定 / 问题 / AI批注 / 人工审核意见 / 照片链接 / 公司反馈）
  ② 全部抽查户（含正常户，供自查）
- **不嵌图**：照片只给 URL（可点击），点开是安检系统原图
- **表上不写年月、不写汇总数字**：公司/月份记在文件名 + 工作簿属性里，公司改不动，回填也不会串月
- **回填**：公司只填最后一列「公司反馈」→ 报告页「导入公司反馈」上传
  （或 `python report_xlsx.py --import 文件.xlsx`）→ 追加进该户审核意见，标 `【公司反馈】`
- 回填**不改判定、不改档位、不动 issues**；同一份文件重复导入不会重复追加
- 集团还没人工审核的户，反馈先存着（`verdict` 留空），不会被算成「已审核」，报告数字不变

## 八、判定口径（现行）

| 项 | 口径 |
|---|---|
| 水印时间 vs 工单时间 | 相差 **≥168 小时（7 天）→ 严重问题**；不足 168 小时不标记（先拍照后补工单属正常） |
| 表号 位数相同 + 后段完全不同 + 非前缀 | 真换表 → **严重问题** |
| 表号 位数相同 + 前缀相近 + 差 1–2 位 | **疑似录入误差** → 一般问题（**不能判严重**） |
| 表号 位数不同 | 两套编码 → 一般问题 |
| 拍不到表 / 读不清 | 一般问题「表号无法辨认」，备注「照片拍摄不清晰！请以后认真拍照！」 |
| 档案表号是占位值（0 / 1 / 888 / 空 / ≤4 位 / 全 0 / 负数） | 一般问题「档案表号异常」——档案录错，不赖安检员 |
| 水印人名 | **不作为问题**（安检员与用户本就是两个人，档案以表格为准） |
| 人工复核三档 | 误判（issues 删除 + 照片存 `false_positive/` 永久留档）/ 一般提示（降级）/ 严重提示（升级） |
| 时间类问题报告 | 只显示文字表格，**不留照片** |
| 数据质量 | 凡读数会翻转结论的（跨月 / 超 7 天 / 边界带），必须回原图再读一次水印行才定稿 |

> **两个最容易判错的点**
> ① 「表号与档案不一致」只能配**严重**；凡是想判一般，一律写「疑似录入误差」。混用会造出假严重。
> ② 拍成广角远景、表号印刷行只有几个像素 → 判「表号无法辨认」，是拍照质量问题，不是造假。

## 九、专项任务怎么用

给「分公司 + 月份 + 人员名单」，做全量复检（不是 10% 抽样）：

```
专项任务：<分公司> 2026-09，名单 张三、李四…，需求是办公会决定复查
```

- 独立库 `ai/special/special.db`，**不写月度主库、不进月度归档**
- 名单内所有可查户全判，月度已判过的沿用原判
- 两个符合率并列：全景（全部户）/ 原口径（月度已判那几户）
- 页面 `/special`，复核在 `/review` 顶栏「专项」下拉里切
- 报告导出到 `安检报告/专项/<任务码>/`

## 十、命令行（进阶）

```bash
cd ai
PY=python                      # 换成你的解释器或 venv 路径

$PY cli.py prepare --file "<xlsx>" --limit 0 --workers 6 --fresh     # 导入+抽样+下载
$PY scripts/batch.py pack --n 32 --company C1 --month 2026-09        # 领一批+生成 checklist
$PY scripts/batch.py gap --pairs "12345=2026-09-02 13:00:04"         # 水印间隔核算（168h 口径）
$PY scripts/batch.py precheck --file reports/_batch24.json           # 提交前预检
$PY cli.py bulk --file reports/_batch24.json                         # 批量交结果
$PY scripts/batch.py postcheck --batch 24                            # 提交后核对
$PY cli.py status                                                    # 进度
$PY cli.py finish --month 2026-09                                    # 收尾统计
```

> `batch.py zoom`（裁切放大）**2026-11 起作废**：读图一律直读原图，读不清就再读一遍原图或直接记「无法辨认」。

## 十二、图片怎么走

**全部走公司服务器外链**，不内嵌、不打字包：

| 场景 | 图从哪来 |
|---|---|
| 网页看（复核 / 报告 / 专项） | 公司图片服务器 URL |
| 导出的 HTML | 同一 URL（六家单月报告通常 1–3 MB） |
| Excel 明细表 | 不含图片，只有链接列 |
| 模型判定 | 本地下载的原图（判完即删） |

所以：**别人拿到报告，只要有网就能看全部照片**；本机硬盘不用囤几十 GB。

## 十三、模型来源

设置页三选一，随时切换，判定口径不变：

1. **DeepSeek 官方** — 推荐 `deepseek-flash`（V4.1 Flash，生产实测）
2. **自定义 API / 中转** — 任何 OpenAI 兼容接口（GLM / Qwen-VL / 各类中转）
3. **Agent 读图** — 不填 Key，由对话里的模型直接看（默认）

选型只看四点：能读清 10–12 位表号小字、能读清水印时间、单图能看清原图细节、额度够跑完当月户数。

## 十四、成本参考

识别由对话模型直接完成时**不产生额外 API 费用、不限流**。
一户判定（读水印 + 读表号 + 核对）约消耗几百个 token，按对话成本计几乎可忽略。
只有启用「程序自动识别模式」（设置页填 Key）才有单独的 token 费用。

## 十五、安全

- API Key 只存本机 `ai/config.json`，不写进代码、不进报告
- 照片全部在本机，除你配置的模型 API 外不上传任何第三方
- Key 若曾在对话中明文出现，建议去平台轮换
